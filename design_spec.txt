2. Design direction: "Night at the Yamuna"

Every visual choice comes from the subject: Krishna, the peacock feather, marigold garlands, river at dusk, oil lamps. Not generic wellness teal-and-white, not a purple AI gradient.

The one memorable thing: the Listening Orb, a large circular recorder in the middle of the voice screen. It breathes slowly when idle, its edge becomes a live waveform while recording, and it settles into the detected emotion's color when analysis finishes. Everything else in the app stays quiet so this one element carries the personality.

Mood words: dusk, lamplight, still water, unhurried, private.

Avoid: cream-and-terracotta "AI editorial" look, neon gradients, glassmorphism everywhere, identical rounded-card grids, emoji as decoration, confetti, stock-photo lotuses, saffron-and-om clichés, ALL-CAPS tracked eyebrow labels above every heading, 01 / 02 / 03 numbering on content that isn't a sequence.

3.4 Spacing & layout
4px base unit. Scale: 4, 8, 12, 16, 24, 32, 48, 72, 112.
Content column: max-width: 1200px, side padding 16px mobile / 32px desktop.
Reading column (guidance, verse): max-width: 680px, centered.
Alignment: left-aligned text by default. Center only the Listening Orb screen and the processing screen.
Touch targets ≥ 48×48px. Primary action sits in the bottom thumb zone on mobile.
3.5 Motion
Ambient motion only in one place: the Listening Orb (slow breathing, 6s ease-in-out loop, scale 1 → 1.04).
All other motion responds to a user action (open, expand, confirm), 160–240ms, cubic-bezier(.2,.7,.2,1).
No staggered fade-up on every section. No hover-lift on every card.
One orchestrated reveal is allowed: on the Guidance page, the verse fades in first, then the advice text, then the audio player (total ≤ 900ms).
Respect prefers-reduced-motion: reduce: replace the breathing and waveform animation with a static ring and a simple level bar; disable the reveal.
4. Core components

Build these in src/components/ and reuse everywhere. Every interactive component needs visible focus (outline: 2px solid var(--peacock); outline-offset: 3px), hover, active, disabled and loading states.

4.1 PrimaryButton
Height 52px, --r-full, background --peacock, text --bg-deep in Night / white in Day, Instrument Sans 600.

loading prop shows a small spinner and keeps width fixed; sets aria-busy.

4.2 VoiceRecorder (the Listening Orb)
Orb diameter: min(72vw, 320px). Background is a radial gradient from --surface-raised to --surface, with a 1px --line ring.
States:
Idle: breathing ring in --peacock. Label inside: "Tap to speak". Under it, a one-line hint: "Tell me what's on your mind. Take as long as you need."
Requesting permission: orb dims; text "Allow microphone access in your browser".
Recording: orb edge becomes a circular waveform driven by AnalyserNode data (use Web Audio API on the same MediaStream already used by MediaRecorder). Show a running timer 0:00 (tabular nums) and a Stop button below. Soft cap at 120s with a gentle "One more minute" notice at 60s.
Review: shows playback of the recording (small linear player), buttons "Use this recording" (primary) and "Record again" (secondary).
Error: mic denied, no mic found, or recording too short (< 2s). Message explains the fix in plain words. Offer the text alternative: "Prefer to type instead?" linking to TextEmotion.
Accessibility: the orb is a <button> with aria-pressed; announce state changes in an aria-live="polite" region.
4.3 EmotionCard / EmotionDisplay
Not a pill-in-a-card. Show: emotion icon (48px, in emotion color), emotion name in H2, a single plain sentence describing it in the product voice (see Copy), and a confidence bar set.
Probability bars: all 7 emotions as horizontal bars sorted descending, top one in its emotion color, the rest in --line. Show percentages with tabular numbers. Bars animate width once on mount only.
EmotionDisplay is the compact variant (icon + name + %), used in history lists.
4.4 AudioPlayer
Custom controls over <audio>: round play/pause button (56px), a seek bar, elapsed/total time, and a speed toggle (0.85×, 1×, 1.15×).
A simple 40-bar static waveform decoration is acceptable; progress fills it from left to right.
Autoplay is never enabled. Show a clear "Play advice" state first.
Loading state: skeleton of the player while the mp3 URL resolves. Error state: "Audio isn't available right now. You can still read the advice below." (do not block the page).
4.4b Loader
Single component with two modes: inline (small ring) and screen (full-screen processing, see 5.7). Replace any bouncing dots with a slow-turning ring so it does not feel frantic.
4.5 Navbar
Mobile: top bar with wordmark left, theme toggle and profile menu right. Primary destinations in a bottom tab bar (Speak, History, Insights) for logged-in users.
Desktop: top bar with wordmark, three text links, profile menu.

4.7 Panels
Use --surface panels with --r-md and a 1px --line border. Vary panel sizes and structure by content; do not present everything as a uniform grid of identical cards. Use dividers and whitespace for grouping when a panel is not needed.

Toasts bottom-center on mobile, top-right on desktop, auto-dismiss 5s, with a close button. Use the same verb as the action: button "Save and continue" → toast "Saved".

A first-time user can go from Landing to hearing their guidance in ≤ 5 taps (excluding permission prompts and sign-up).
The Listening Orb is the only element with ambient animation anywhere in the app.
Every emotion is identifiable by icon and label, not only by color.
Every screen has designed loading, empty and error states.
Lighthouse (mobile): Accessibility ≥ 95, Best Practices ≥ 90.
No API, route, or env-var changes. npm run build completes with zero errors.
The app feels calm: no flashing, no auto-playing audio, no countdown pressure, no gamified streak mechanics that guilt the user.
